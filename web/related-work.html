Prior Work

Papers, advisories and tools this project builds on or deliberately does not over-claim against.

Measurement study

Mining Your Ps and Qs: Detection of Widespread Weak Keys in Network Devices

Heninger, Durumeric, Wustrow, Halderman · USENIX Security 2012

Internet-wide scans found many embedded devices sharing RSA primes because they generated keys with too little entropy at first boot. RSAShield's batch-GCD detector and its headless-device threat model come straight from this result.

Structured primes

The Return of Coppersmith's Attack (ROCA)

Nemec, Sýs, Švenda, Klinec, Matyáš · CCS 2017 · CVE-2017-15361

A widely deployed library generated primes with recognisable structure, making keys fingerprintable and factorable. It motivates the “structured prime” failure mode and the vendor-advisory remediation path.

Batch GCD with product and remainder trees

Bernstein · quasi-linear all-pairs GCD

Finds every shared prime across N moduli without comparing all pairs one by one. RSAShield implements the tree form and checks it against the naïve pairwise version in its tests.

The Gaps RSAShield Fills

From the project's gap analysis — each row is a measurable contribution, not a new algorithm.

#Gap in existing tools & literatureWhat RSAShield adds
G1Tools detect, but almost none ship a controlled benchmark with ground truth; scan studies have no labels.A reproducible, fault-injected, labelled benchmark with per-detector precision, recall and runtime.
G2ECM's role is usually hand-waved or omitted.A bounded-ECM budget with a measured marginal-yield study.
G3No tool frames findings for ICS / substation constraints.Remediation context for long-lived grid keys, mapped to IEC 62351 and NERC CIP.
G4Binary weak / not-weak output; some tools imply “secure”.A multi-signal risk score that never labels a key secure — only “no defect found under budget”.
G5No mapping from a positive signal to the generation defect that caused it.A detector → failure-mode attribution that drives the remediation advice.
